# KIẾN TRÚC HỆ THỐNG - MICROSERVICES

## 1. TỔNG QUAN KIẾN TRÚC

### 1.1. Mô hình tổng thể
Hệ thống sử dụng kiến trúc **Microservices** với các đặc điểm:
- **Loosely coupled services**: Mỗi service độc lập, communicate qua API
- **Technology diversity**: Sử dụng FastAPI (Python) cho backend services
- **Containerization**: Mỗi service chạy trong Docker container riêng
- **Database per service**: Mỗi service có database riêng (hoặc schema riêng)
- **API Gateway**: Centralized entry point cho tất cả requests
- **Service Discovery**: Tự động phát hiện và routing

### 1.2. Lý do chọn Microservices
**Ưu điểm:**
- **Scalability**: Scale từng service độc lập theo nhu cầu
- **Technology flexibility**: Dễ dàng thay đổi công nghệ cho từng service
- **Fault isolation**: Lỗi ở một service không ảnh hưởng toàn hệ thống
- **Team autonomy**: Team khác nhau phát triển service khác nhau
- **Continuous deployment**: Deploy từng service mà không ảnh hưởng toàn bộ

**Nhược điểm (và cách giải quyết):**
- **Complexity**: Sử dụng Docker Compose để đơn giản hóa deployment
- **Data consistency**: Sử dụng event-driven architecture khi cần
- **Monitoring**: Tập trung logging và monitoring

## 2. MICROSERVICES BREAKDOWN

### 2.1. Auth Service (Authentication & Authorization)
**Trách nhiệm:**
- Đăng nhập (Local + Active Directory)
- Multi-Factor Authentication (MFA) với OTP
- JWT token generation & validation
- Refresh token management
- Password reset
- User management (CRUD)
- Role & Permission management
- Active Directory synchronization

**Technology Stack:**
- **Framework**: FastAPI
- **ORM**: SQLAlchemy
- **Auth**: python-jose (JWT), passlib (password hashing)
- **MFA/OTP**: pyotp (TOTP generator)
- **Active Directory**: ldap3 (LDAP client)
- **Database**: PostgreSQL (schema: auth_db)

**API Endpoints:**
- `POST /api/v1/auth/login` (Step 1: Email/Password)
- `POST /api/v1/auth/verify-otp` (Step 2: OTP verification)
- `POST /api/v1/auth/logout`
- `POST /api/v1/auth/refresh`
- `POST /api/v1/auth/forgot-password`
- `GET /api/v1/auth/mfa/setup` (Generate QR code for MFA setup)
- `POST /api/v1/auth/mfa/enable` (Enable MFA)
- `POST /api/v1/auth/mfa/disable` (Disable MFA)
- `GET/POST/PUT /api/v1/auth/users`
- `GET/POST /api/v1/auth/roles`
- `POST /api/v1/auth/sync-ad` (Sync users from Active Directory)

**Database Tables:**
- users
  - user_type: `local` | `active_directory`
  - mfa_enabled: boolean
  - mfa_secret: encrypted TOTP secret
  - ad_sync_id: Active Directory user ID
  - require_passwd_change: Require to change password next login
- roles
- permissions
- user_roles
- refresh_tokens
- password_reset_tokens
- mfa_backup_codes (for recovery)

**Docker Container:**
```yaml
auth-service:
  build: ./services/auth
  ports:
    - "8001:8000"
  environment:
    - DATABASE_URL=postgresql://user:pass@postgres/auth_db
    - JWT_SECRET=secret
    - REDIS_URL=redis://redis:6379
    - MFA_ISSUER=AssetManagement
    - AD_SERVER=ldap://ad.company.com
    - AD_DOMAIN=company.com
    - AD_BIND_DN=CN=admin,DC=company,DC=com
    - AD_BIND_PASSWORD=ad_password
    - AD_SEARCH_BASE=OU=Users,DC=company,DC=com
  depends_on:
    - postgres
    - redis
```

## 3. SHARED INFRASTRUCTURE

### 3.1. API Gateway
**Technology**: Nginx hoặc Kong
**Trách nhiệm:**
- Reverse proxy & load balancing
- Rate limiting
- CORS handling
- SSL termination
- Request routing based on URL path
- Authentication middleware (verify JWT)

**Nginx Configuration Example:**
```nginx
upstream auth-service {
    server auth-service:8000;
}

upstream asset-service {
    server asset-service:8000;
}

server {
    listen 80;
    server_name api.assetmanagement.com;

    location /api/v1/auth/ {
        proxy_pass http://auth-service/api/v1/auth/;
    }

    location /api/v1/assets/ {
        proxy_pass http://asset-service/api/v1/assets/;
    }

    # Rate limiting
    limit_req_zone $binary_remote_addr zone=api_limit:10m rate=10r/s;
    limit_req zone=api_limit burst=20;
}
```

## 4. INTER-SERVICE COMMUNICATION

### 4.1. Synchronous Communication (HTTP/REST)
**Khi nào sử dụng:**
- Request-response immediate
- Cần dữ liệu ngay lập tức

**Example:**
- Report Service gọi Asset Service để lấy danh sách assets
- Procurement Service gọi Auth Service để verify user permissions

**Implementation:**
- `httpx` (async HTTP client trong FastAPI)
- Service discovery: Environment variables chứa URLs

### 4.2. Asynchronous Communication (Events)
**Khi nào sử dụng:**
- Fire-and-forget
- Multiple consumers
- Decoupling services

**Example:**
- Purchase Request được approved → Publish event `purchase_request.approved`
  - Notification Service nhận event → Gửi email
  - Procurement Service nhận event → Cập nhật workflow

**Implementation:**
- RabbitMQ với Pika library
- Event structure:
```json
{
  "event_type": "purchase_request.approved",
  "timestamp": "2025-10-17T10:00:00Z",
  "data": {
    "request_id": "PR-2025-001",
    "requester_id": 123,
    "approver_id": 456
  }
}
```

## 5. FASTAPI SERVICE STRUCTURE

### 5.1. Project Structure (per service)

**YÊU CẦU QUAN TRỌNG**:
- Tất cả các service PHẢI sử dụng **Repository Pattern** và **Unit of Work Pattern** để quản lý data access layer
- Tất cả các service PHẢI sử dụng **CQRS Pattern** để tách biệt Command (Write) và Query (Read) operations
- Tất cả các service PHẢI sử dụng **RabbitMQ** để trao đổi dữ liệu giữa các services

### 5.2. FastAPI main.py Example
```python
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware
from app.core.database import engine
from app.models import Base
from app.api.v1.router import api_router
from app.core.events import startup_event, shutdown_event

# Create tables
Base.metadata.create_all(bind=engine)

app = FastAPI(
    title="Asset Management - Auth Service",
    version="1.0.0",
    docs_url="/api/docs",
    redoc_url="/api/redoc"
)

# CORS
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)

# Include routers
app.include_router(api_router, prefix="/api/v1")

# Startup & shutdown events
@app.on_event("startup")
async def startup():
    await startup_event()

@app.on_event("shutdown")
async def shutdown():
    await shutdown_event()

@app.get("/health")
async def health_check():
```

### 5.6. Repository Pattern Implementation

**YÊU CẦU**: Tất cả các tác vụ làm việc với database PHẢI sử dụng Repository Pattern để tách biệt logic truy xuất dữ liệu khỏi business logic.

#### 5.6.1. Base Repository
```python
# app/repositories/base_repository.py
from typing import TypeVar, Generic, Type, List, Optional
from sqlalchemy.orm import Session
from sqlalchemy import and_

T = TypeVar('T')

class BaseRepository(Generic[T]):
    """
    Generic Repository cung cấp CRUD operations cơ bản
    """
    def __init__(self, model: Type[T], db: Session):
        self.model = model
        self.db = db

    def get_by_id(self, id: int) -> Optional[T]:
        """Lấy entity theo ID"""
        return self.db.query(self.model).filter(self.model.id == id).first()

    def get_all(self, skip: int = 0, limit: int = 100) -> List[T]:
        """Lấy tất cả entities với pagination"""
        return self.db.query(self.model).offset(skip).limit(limit).all()

    def get_by_filter(self, **filters) -> List[T]:
        """Lấy entities theo filter"""
        query = self.db.query(self.model)
        for key, value in filters.items():
            if hasattr(self.model, key):
                query = query.filter(getattr(self.model, key) == value)
        return query.all()

    def create(self, entity: T) -> T:
        """Tạo mới entity"""
        self.db.add(entity)
        self.db.flush()  # Flush để có ID nhưng chưa commit
        self.db.refresh(entity)
        return entity

    def update(self, entity: T) -> T:
        """Cập nhật entity"""
        self.db.merge(entity)
        self.db.flush()
        self.db.refresh(entity)
        return entity

    def delete(self, id: int) -> bool:
        """Xóa entity theo ID"""
        entity = self.get_by_id(id)
        if entity:
            self.db.delete(entity)
            self.db.flush()
            return True
        return False

    def exists(self, id: int) -> bool:
        """Kiểm tra entity có tồn tại không"""
        return self.db.query(self.model.id).filter(self.model.id == id).scalar() is not None

    def count(self, **filters) -> int:
        """Đếm số lượng entities"""
        query = self.db.query(self.model)
        for key, value in filters.items():
            if hasattr(self.model, key):
                query = query.filter(getattr(self.model, key) == value)
        return query.count()
```

### 5.7. Unit of Work Pattern Implementation

**YÊU CẦU**: Tất cả các transactions phức tạp (thao tác trên nhiều entities) PHẢI sử dụng Unit of Work Pattern để đảm bảo tính nhất quán dữ liệu.

#### 5.7.1. Unit of Work Implementation
```python
# app/core/unit_of_work.py
from typing import Optional
from sqlalchemy.orm import Session
from app.core.database import SessionLocal
from app.repositories.user_repository import UserRepository
from app.repositories.asset_repository import AssetRepository
from app.repositories.purchase_request_repository import PurchaseRequestRepository
# Import thêm các repositories khác...

class UnitOfWork:
    """
    Unit of Work Pattern quản lý transactions và repositories

    Đảm bảo:
    - Tất cả operations trong một business transaction dùng chung 1 DB session
    - Commit/Rollback toàn bộ hoặc không commit gì cả (atomicity)
    - Tự động cleanup resources
    """

    def __init__(self, db: Optional[Session] = None):
        self.db = db or SessionLocal()
        self._should_close_session = db is None

        # Khởi tạo repositories (lazy loading)
        self._user_repository: Optional[UserRepository] = None
        self._asset_repository: Optional[AssetRepository] = None
        self._purchase_request_repository: Optional[PurchaseRequestRepository] = None
        # Thêm các repositories khác...

    @property
    def users(self) -> UserRepository:
        """Lazy load User Repository"""
        if self._user_repository is None:
            self._user_repository = UserRepository(self.db)
        return self._user_repository

    @property
    def assets(self) -> AssetRepository:
        """Lazy load Asset Repository"""
        if self._asset_repository is None:
            self._asset_repository = AssetRepository(self.db)
        return self._asset_repository

    @property
    def purchase_requests(self) -> PurchaseRequestRepository:
        """Lazy load Purchase Request Repository"""
        if self._purchase_request_repository is None:
            self._purchase_request_repository = PurchaseRequestRepository(self.db)
        return self._purchase_request_repository

    def commit(self):
        """Commit transaction"""
        self.db.commit()

    def rollback(self):
        """Rollback transaction"""
        self.db.rollback()

    def close(self):
        """Close database session"""
        if self._should_close_session:
            self.db.close()

    def __enter__(self):
        """Context manager entry"""
        return self

    def __exit__(self, exc_type, exc_val, exc_tb):
        """Context manager exit - auto commit/rollback"""
        try:
            if exc_type is None:
                self.commit()
            else:
                self.rollback()
        finally:
            self.close()
```

#### 5.7.2. Using Unit of Work in Services
```python
# app/services/asset_service.py
from typing import List, Optional
from app.core.unit_of_work import UnitOfWork
from app.schemas.asset import AssetCreate, AssetUpdate
from app.models.asset import Asset
from app.models.asset_history import AssetHistory
from datetime import datetime

class AssetService:
    """
    Service layer chứa business logic
    Sử dụng UnitOfWork để đảm bảo data consistency
    """

    @staticmethod
    def create_asset(asset_data: AssetCreate) -> Asset:
        """
        Tạo asset mới và ghi lại lịch sử
        """
        with UnitOfWork() as uow:
            # Kiểm tra mã tài sản đã tồn tại chưa
            existing = uow.assets.get_by_asset_code(asset_data.asset_code)
            if existing:
                raise ValueError(f"Asset code {asset_data.asset_code} already exists")

            # Tạo asset
            asset = Asset(**asset_data.dict())
            created_asset = uow.assets.create(asset)

            # Ghi lại lịch sử
            history = AssetHistory(
                asset_id=created_asset.id,
                action="CREATED",
                timestamp=datetime.now(),
                details=f"Asset {created_asset.asset_code} created"
            )
            uow.asset_histories.create(history)

            # UnitOfWork tự động commit khi exit context
            return created_asset

    @staticmethod
    def assign_asset_to_user(asset_id: int, user_id: int, assigned_by: int) -> Asset:
        """
        Cấp phát asset cho user
        Transaction phức tạp: cập nhật asset, tạo assignment record, ghi lịch sử
        """
        with UnitOfWork() as uow:
            # Lấy asset
            asset = uow.assets.get_by_id(asset_id)
            if not asset:
                raise ValueError(f"Asset {asset_id} not found")

            # Kiểm tra asset có thể cấp phát không
            if asset.status not in ["NEW", "AVAILABLE"]:
                raise ValueError(f"Asset {asset.asset_code} is not available for assignment")

            # Kiểm tra user tồn tại
            user = uow.users.get_by_id(user_id)
            if not user:
                raise ValueError(f"User {user_id} not found")

            # Cập nhật asset
            asset.assigned_to = user_id
            asset.status = "IN_USE"
            asset.assigned_date = datetime.now()
            updated_asset = uow.assets.update(asset)

            # Tạo assignment record
            from app.models.asset_assignment import AssetAssignment
            assignment = AssetAssignment(
                asset_id=asset_id,
                user_id=user_id,
                assigned_by=assigned_by,
                assigned_date=datetime.now()
            )
            uow.asset_assignments.create(assignment)

            # Ghi lịch sử
            history = AssetHistory(
                asset_id=asset_id,
                action="ASSIGNED",
                timestamp=datetime.now(),
                user_id=assigned_by,
                details=f"Asset assigned to user {user.full_name}"
            )
            uow.asset_histories.create(history)

            # UnitOfWork tự động commit tất cả changes
            return updated_asset

    @staticmethod
    def reclaim_asset(asset_id: int, reclaimed_by: int, reason: str) -> Asset:
        """
        Thu hồi asset từ user
        """
        with UnitOfWork() as uow:
            asset = uow.assets.get_by_id(asset_id)
            if not asset:
                raise ValueError(f"Asset {asset_id} not found")

            if asset.status != "IN_USE":
                raise ValueError(f"Asset {asset.asset_code} is not currently assigned")

            # Lưu thông tin user cũ
            old_user_id = asset.assigned_to
            old_user = uow.users.get_by_id(old_user_id) if old_user_id else None

            # Cập nhật asset
            asset.assigned_to = None
            asset.status = "AVAILABLE"
            asset.reclaimed_date = datetime.now()
            updated_asset = uow.assets.update(asset)

            # Cập nhật assignment record
            from app.models.asset_assignment import AssetAssignment
            assignment = uow.asset_assignments.get_active_assignment(asset_id)
            if assignment:
                assignment.reclaimed_date = datetime.now()
                assignment.reclaimed_by = reclaimed_by
                assignment.reclaim_reason = reason
                uow.asset_assignments.update(assignment)

            # Ghi lịch sử
            history = AssetHistory(
                asset_id=asset_id,
                action="RECLAIMED",
                timestamp=datetime.now(),
                user_id=reclaimed_by,
                details=f"Asset reclaimed from {old_user.full_name if old_user else 'unknown'}. Reason: {reason}"
            )
            uow.asset_histories.create(history)

            return updated_asset
```

### 5.8. Benefits of Repository + Unit of Work Patterns

**Lợi ích chính:**

1. **Separation of Concerns**
   - Business logic (Services) tách biệt khỏi data access logic (Repositories)
   - Dễ maintain và test

2. **Testability**
   - Có thể mock repositories trong unit tests
   - Test business logic mà không cần database thật

3. **Consistency**
   - UnitOfWork đảm bảo ACID properties
   - Tất cả changes trong một transaction được commit/rollback cùng nhau

4. **Reusability**
   - Repositories có thể được reuse ở nhiều services
   - Tránh duplicate query code

5. **Maintainability**
   - Thay đổi database queries chỉ cần sửa ở repository
   - Không ảnh hưởng đến business logic

6. **Performance**
   - Dễ dàng thêm caching ở repository layer
   - Optimize queries tại một điểm duy nhất

**Best Practices:**

- ❌ **KHÔNG BAO GIỜ** query database trực tiếp trong API endpoints
- ❌ **KHÔNG BAO GIỜ** query database trực tiếp trong Services
- ✅ **LUÔN LUÔN** sử dụng Repositories để truy xuất dữ liệu
- ✅ **LUÔN LUÔN** sử dụng UnitOfWork cho transactions phức tạp
- ✅ **LUÔN LUÔN** handle exceptions trong Services và API endpoints
- ✅ Mỗi Repository chỉ quản lý 1 entity (Single Responsibility)
- ✅ Business logic nằm trong Services, không nằm trong Repositories

## 5A. CQRS PATTERN (COMMAND QUERY RESPONSIBILITY SEGREGATION)

### 5A.1. CQRS Overview

**YÊU CẦU**: Tất cả services PHẢI sử dụng CQRS Pattern để tách biệt operations ghi (Commands) và đọc (Queries).

**Kiến trúc CQRS:**
```
                         ┌──────────────────────────────────────┐
                         │         API Endpoints                │
                         └──────────┬──────────────┬────────────┘
                                    │              │
                    ┌───────────────┘              └───────────────┐
                    ↓                                              ↓
         ┌──────────────────────┐                      ┌──────────────────────┐
         │   COMMAND SIDE       │                      │    QUERY SIDE        │
         │   (Write Model)      │                      │   (Read Model)       │
         └──────────────────────┘                      └──────────────────────┘
                    │                                              │
                    ↓                                              ↓
         ┌──────────────────────┐                      ┌──────────────────────┐
         │  Command Handlers    │                      │   Query Handlers     │
         └──────────┬───────────┘                      └──────────┬───────────┘
                    │                                              │
                    ↓                                              ↓
         ┌──────────────────────┐                      ┌──────────────────────┐
         │   UnitOfWork +       │                      │  Read Repositories   │
         │   Repositories       │                      │   (MongoDB)          │
         └──────────┬───────────┘                      └──────────────────────┘
                    │                                              ↑
                    ↓                                              │
         ┌──────────────────────┐         Events        ┌─────────┴────────────┐
         │  PostgreSQL          │──────────────────────→│  Event Handlers      │
         │  (Write DB)          │      (RabbitMQ)       │  (Sync to Read DB)   │
         └──────────────────────┘                       └──────────────────────┘
```

**Lợi ích:**
- **Performance**: Read model được optimize riêng cho queries (denormalized)
- **Scalability**: Scale read và write independently
- **Flexibility**: Có thể dùng DB khác nhau cho read/write
- **Simplified Queries**: Read model đơn giản, không cần complex joins

```python
# app/core/message_bus.py
from typing import Dict, Type, Union
from app.commands.base_command_handler import BaseCommandHandler
from app.queries.base_query_handler import BaseQueryHandler

class MessageBus:
    """
    Message Bus để dispatch commands và queries tới handlers tương ứng
    """
    def __init__(self):
        self._command_handlers: Dict[Type, BaseCommandHandler] = {}
        self._query_handlers: Dict[Type, BaseQueryHandler] = {}

    def register_command_handler(
        self,
        command_type: Type,
        handler: BaseCommandHandler
    ):
        """Đăng ký command handler"""
        self._command_handlers[command_type] = handler

    def register_query_handler(
        self,
        query_type: Type,
        handler: BaseQueryHandler
    ):
        """Đăng ký query handler"""
        self._query_handlers[query_type] = handler

    async def execute_command(self, command):
        """
        Execute command thông qua handler tương ứng
        """
        command_type = type(command)
        handler = self._command_handlers.get(command_type)

        if not handler:
            raise ValueError(f"No handler registered for {command_type}")

        return await handler.handle(command)

    async def execute_query(self, query):
        """
        Execute query thông qua handler tương ứng
        """
        query_type = type(query)
        handler = self._query_handlers.get(query_type)

        if not handler:
            raise ValueError(f"No handler registered for {query_type}")

        return await handler.handle(query)

# Singleton instance
_message_bus = MessageBus()

def get_message_bus() -> MessageBus:
    """Dependency injection cho MessageBus"""
    return _message_bus
```

### 5B.2. RabbitMQ Connection Setup

```python
# app/core/rabbitmq.py
import aio_pika
import json
from typing import Dict, Callable
from app.config import settings

class RabbitMQConnection:
    """
    RabbitMQ connection manager
    Singleton pattern
    """
    _instance = None
    _connection = None
    _channel = None

    def __new__(cls):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance

    async def connect(self):
        """Establish connection to RabbitMQ"""
        if self._connection is None or self._connection.is_closed:
            self._connection = await aio_pika.connect_robust(
                settings.RABBITMQ_URL
            )
            self._channel = await self._connection.channel()
            print("Connected to RabbitMQ")

    async def close(self):
        """Close connection"""
        if self._channel:
            await self._channel.close()
        if self._connection:
            await self._connection.close()

    async def get_channel(self):
        """Get channel for publishing/consuming"""
        if not self._channel or self._channel.is_closed:
            await self.connect()
        return self._channel

# Global instance
rabbitmq = RabbitMQConnection()

async def publish_event(event: dict, exchange_name: str = "asset.events"):
    """
    Publish event to RabbitMQ

    Args:
        event: Event data (dict with event_type, timestamp, data)
        exchange_name: Exchange to publish to
    """
    channel = await rabbitmq.get_channel()

    # Declare exchange (idempotent)
    exchange = await channel.declare_exchange(
        exchange_name,
        aio_pika.ExchangeType.TOPIC,
        durable=True
    )

    # Publish message
    routing_key = event["event_type"]  # e.g., "asset.created"
    message = aio_pika.Message(
        body=json.dumps(event).encode(),
        delivery_mode=aio_pika.DeliveryMode.PERSISTENT
    )

    await exchange.publish(message, routing_key=routing_key)
    print(f"Published event: {routing_key}")

async def consume_events(
    exchange_name: str,
    queue_name: str,
    routing_keys: list,
    callback: Callable
):
    """
    Consume events from RabbitMQ

    Args:
        exchange_name: Exchange to consume from
        queue_name: Queue name
        routing_keys: List of routing keys to bind (e.g., ["asset.created", "asset.updated"])
        callback: Async function to handle messages
    """
    channel = await rabbitmq.get_channel()

    # Declare exchange
    exchange = await channel.declare_exchange(
        exchange_name,
        aio_pika.ExchangeType.TOPIC,
        durable=True
    )

    # Declare queue
    queue = await channel.declare_queue(queue_name, durable=True)

    # Bind queue to exchange with routing keys
    for routing_key in routing_keys:
        await queue.bind(exchange, routing_key=routing_key)

    # Start consuming
    async with queue.iterator() as queue_iter:
        async for message in queue_iter:
            async with message.process():
                event_data = json.loads(message.body.decode())
                await callback(event_data)
```

**Lợi ích:**

2. **Performance**: Read queries cực nhanh (denormalized MongoDB)
3. **Scalability**: Scale read và write services independently
4. **Loose Coupling**: Services giao tiếp qua events, không call trực tiếp
5. **Reliability**: RabbitMQ ensures message delivery (persistent queues)
6. **Auditability**: Events log tất cả changes trong hệ thống

**Best Practices:**

- ✅ Commands modify state (write DB), sau đó publish events
- ✅ Queries chỉ đọc từ Read DB (MongoDB), KHÔNG modify state
- ✅ Event handlers sync Write DB → Read DB asynchronously
- ✅ Use idempotent event handlers (handle duplicate events gracefully)
- ✅ Versioning cho events để support backward compatibility
- ❌ KHÔNG call services trực tiếp, sử dụng events
- ❌ KHÔNG write vào Read DB từ Commands, chỉ qua events

## 7. BẢO MẬT

### 7.1. Authentication & Authorization

#### 7.1.1. Multi-Factor Authentication (MFA)
**Two-Step Login Process:**
1. **Step 1**: Email/Password authentication
   - Validate credentials (local hoặc Active Directory)
   - Return temp_token (valid 5 minutes)
2. **Step 2**: OTP verification
   - User nhập OTP từ Authenticator app
   - Validate OTP với TOTP secret
   - Return access_token + refresh_token

**MFA Setup Flow:**
1. User enable MFA trong settings
2. System generate TOTP secret
3. Return QR code (format: `otpauth://totp/AssetManagement:user@email.com?secret=SECRET&issuer=AssetManagement`)
4. User quét QR bằng Google Authenticator / Authy
5. User nhập OTP để verify
6. System lưu mfa_secret (encrypted) vào database

**Backup Codes:**
- Generate 10 one-time backup codes khi enable MFA
- User có thể dùng backup code thay OTP
- Mỗi code chỉ dùng 1 lần

**Active Directory Integration:**
```python
import ldap3

def authenticate_ad(username, password):
    server = ldap3.Server(AD_SERVER, get_info=ldap3.ALL)
    conn = ldap3.Connection(
        server,
        user=f"{username}@{AD_DOMAIN}",
        password=password,
        authentication=ldap3.SIMPLE
    )

    if conn.bind():
        # Search for user info
        search_filter = f"(sAMAccountName={username})"
        conn.search(
            search_base=AD_SEARCH_BASE,
            search_filter=search_filter,
            attributes=['mail', 'displayName', 'department']
        )
        user_info = conn.entries[0]
        return {
            "email": user_info.mail.value,
            "full_name": user_info.displayName.value,
            "department": user_info.department.value
        }
    return None
```

**JWT-based Authentication:**
- Access Token: 8 giờ
- Refresh Token: 7 ngày
- Lưu Refresh Token trong database, có thể revoke

**Password Security:**
- Bcrypt hashing (cost factor: 12)
- Password policy: Min 8 chars, chữ hoa + chữ thường + số
- AD users: password được verify qua LDAP

**API Security:**
- Tất cả endpoints (trừ login) yêu cầu JWT token
- Middleware verify token ở API Gateway và mỗi service
- Rate limiting: 100 req/min/IP

### 9.2. Caching Strategy
**Redis Cache:**
- Cache frequently accessed data (asset details, categories)
- TTL: 5-60 phút
- Cache invalidation khi data update

```python
import redis
import json

redis_client = redis.Redis(host='redis', port=6379, decode_responses=True)

async def get_asset(asset_id: int, db: Session):
    # Try cache first
    cache_key = f"asset:{asset_id}"
    cached = redis_client.get(cache_key)
    if cached:
        return json.loads(cached)

    # Query DB
    asset = db.query(Asset).filter(Asset.id == asset_id).first()
    if asset:
        # Cache it
        redis_client.setex(cache_key, 300, json.dumps(asset.dict()))
    return asset
```
